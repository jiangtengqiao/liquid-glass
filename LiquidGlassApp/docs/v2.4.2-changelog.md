## 检查更新查找不到新版 — 根因修复

### 根因

v2.4.1 的检查更新代码把 jsdelivr CDN 放在源列表第一位优先用，GitHub raw 放最后兜底：

```kotlin
// AboutScreen.kt (v2.4.1)
val urls = listOf(
    "https://cdn.jsdelivr.net/gh/jiangtengqiao/liquid-glass@main/version.json?t=$cacheBust",
    "https://fastly.jsdelivr.net/gh/jiangtengqiao/liquid-glass@main/version.json?t=$cacheBust",
    "https://raw.githubusercontent.com/jiangtengqiao/liquid-glass/main/version.json?t=$cacheBust"
)
```

但 jsdelivr 对 GitHub 仓库（`/gh/` 路径）的缓存策略是：**最长缓存 12 小时以上，且 `?t=` 时间戳参数对 `gh` 仓库缓存完全无效**（jsdelivr 会忽略查询参数按路径缓存）。

实测三个源同时拉取：

| 源 | 返回版本 | versionCode |
|---|---|---|
| `cdn.jsdelivr.net` | 2.2.0 | 5 |
| `fastly.jsdelivr.net` | 2.2.1 | 6 |
| `raw.githubusercontent.com` | 2.4.1 | 15（正确）|

jsdelivr 还停留在 2.2.0/2.2.1 的旧缓存。代码取第一个源（jsdelivr）返回的 versionCode=5，与用户当前 versionCode=15 比较：`5 > 15` 为 false → 走「已是最新版」分支 → **用户永远查找不到新版**。

### 修复

1. **源顺序调整：GitHub raw 优先**
   ```kotlin
   val urls = listOf(
       "https://raw.githubusercontent.com/jiangtengqiao/liquid-glass/main/version.json?t=$cacheBust",
       "https://cdn.jsdelivr.net/gh/jiangtengqiao/liquid-glass@main/version.json?t=$cacheBust",
       "https://fastly.jsdelivr.net/gh/jiangtengqiao/liquid-glass@main/version.json?t=$cacheBust"
   )
   ```
   GitHub raw 实时不缓存，永远返回 main 分支最新内容。

2. **新增脏缓存检测**
   ```kotlin
   val remoteVc = parsed.optInt("versionCode", 0)
   if (currentVersionCodePre > 0 && remoteVc in 1..(currentVersionCodePre - 1)) {
       lastError = "源返回旧版本 v${parsed.optString("version")} (vc=$remoteVc)，疑似CDN缓存，切换源"
       continue
   }
   ```
   即便 GitHub raw 偶发不可达降级到 jsdelivr，也能识别出脏缓存并继续切换源。

3. **请求头加 `Cache-Control: no-cache`**

4. **失败提示更明确**：显示具体失败原因，不再笼统说「网络不可达」

### 效果
- GitHub raw 优先 → 永远拿到最新 version.json
- 即便 raw 不可达降级 jsdelivr → 脏缓存检测会跳过旧版本继续尝试
- 三重保险：源顺序 + 脏缓存检测 + 明确失败提示
